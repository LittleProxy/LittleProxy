# Server connection pool selection via the Java ServiceLoader

The `ServerConnectionPoolType` enum was removed and replaced by a ServiceLoader SPI: `ServerConnectionPool` is itself the SPI contract (`getName()` + `initialize(ServerConnectionPoolContext)`), implementations are selected by a string name (`withServerConnectionPoolName(...)` or `server_connection_pool_name` in the properties file), and `ServerConnectionPoolLoader` falls back to the built-in `CONCURRENT_MAP` when the name is unknown or nothing is registered. Each implementation configures itself from an option map in the context, so implementation-specific settings no longer have to fit the fixed `ServerConnectionPoolConfig` bean.

Considered options, rejected: loading the pool directly through a no-arg constructor without an initialize lifecycle (rejected — SPI lifecycle would still need to live somewhere, and explicit `initialize` was wanted for fail-fast configuration); a separate provider/factory interface registered in `META-INF/services` (rejected — the pool itself is the natural SPI here; a second interface added build-time indirection for no runtime benefit); a strictly typed per-implementation config class (rejected in favor of the option map, which lets external implementations accept their own keys). Selection by name rather than ServiceLoader order avoids surprising default-picks when several jars contribute pools. Removing the enum is a deliberate API break: it only ever had one value, so keeping it would have duplicated the name-resolution machinery for no compat gain.
